# Сегментные лендинги TutorOnline

Три лендинга под холодный трафик Avito, Wildberries и Ozon с квиз-формой брони бесплатного пробного урока:

| Сегмент | Адрес | Аудитория | Тема | Доп. блок |
|---|---|---|---|---|
| 1–4 класс | `/1-4/` | родитель, тёплый тон | `light` | — |
| 5–9 класс | `/5-9/` | родитель, деловой тон | `light` | ОГЭ |
| 10–11 класс | `/10-11/` | ученик, на «ты» | `contrast` | «Родителям» |

Фреймворков и бандлеров нет: страницы собираются Node-скриптом из JSON-контента и шаблонов, браузер получает готовый HTML и ES-модули без транспиляции. Заявки принимает `server.mjs` и передаёт в CRM тем же вебхуком, что и базовый лендинг.

## Требования

Node.js **22 или новее** (`package.json` → `engines`).

На Node 16 проект частично работает, но с оговорками: сборка идёт, `npm start` падает с `ReferenceError: fetch is not defined` (лечится запуском `node --experimental-fetch server.mjs`), а `npm test` не запускается вовсе — в скрипте используется `node --test --test-concurrency`.

## Быстрый старт

```sh
npm install          # ставит только @playwright/test (dev)
npm run build        # src/ + content/ → dist/, затем проверка бюджетов
npm start            # http://127.0.0.1:8765/5-9/
```

| Команда | Что делает |
|---|---|
| `npm run build` | Собирает `dist/` и печатает размеры (CSS ≤ 40 КБ, JS ≤ 30 КБ gzip) |
| `npm run build:strict` | То же плюс строгие проверки контента: заполнены все блоки сегментов, задан `promoCode`. Включается и через `NODE_ENV=production` |
| `npm start` | Поднимает сервер на `dist/` (порт `PORT`, по умолчанию 8765) |
| `npm test` | Unit- и серверные тесты (`node --test`) |
| `npm run test:e2e` | Playwright: Chromium и WebKit × 5 ширин (360, 390, 768, 1024, 1440). Первый запуск: `npx playwright install` |

Сервер отдаёт только `dist/`. Если запустить его без сборки, страницы вернут 404.

## Структура

```text
landings/
├── build.mjs              # сборка: контент + шаблоны → dist/, хэши ассетов и инлайн-скриптов
├── server.mjs             # раздача страниц, cookie посетителя, POST /api/lead → CRM
├── src/
│   ├── content/           # ВЕСЬ редактируемый текст и параметры (JSON)
│   ├── templates/         # html.mjs, page.mjs, blocks/* — разметка 10 блоков каркаса
│   ├── css/               # tokens → base → components → themes (склеиваются в этом порядке)
│   └── js/                # main.mjs + модули: quiz, scarcity, floating, analytics, lib/*
├── assets/                # шрифты WOFF2, фото репетиторов WebP/AVIF, иконки, логотипы
├── tools/                 # вспомогательные скрипты (см. ниже)
├── tests/                 # unit/, server/, e2e/
└── dist/                  # результат сборки, в .gitignore
```

Логика без DOM вынесена в `src/js/lib/*.mjs` и `quiz-state.mjs` — она же тестируется в Node и работает в браузере без сборки.

## Контент: всё правится в JSON

Код трогать не нужно — тексты, цены и параметры живут в `src/content/`.

### `segments/{1-4,5-9,10-11}.json` — тексты сегмента

Ключевые поля: `meta` (title, description), `topbar` (строка таймера и шаблон мест), `hero.a` / `hero.b` (два варианта первого экрана), `pains` (ровно 3 карточки), `trialSteps` (3–4 шага), `faq` (не меньше 4), `final`, `quizVariant.a` / `.b` (заголовки трёх шагов формы), `heroTutorIds`, `extraBlocks` (`oge`, `parents`), `defaultGrade` (предвыбранный класс: 2, 7, 11).

Предметы сегмента — `subjects` (порядок = порядок чипов в форме, первый выбран по умолчанию) и `tutorIds` по каждому предмету. Сборка падает, если предмета нет в `site.json` → `subjects` или если для него не задан ни один репетитор:

| Сегмент | Предметы |
|---|---|
| 1–4 | математика, русский язык |
| 5–9 | + физика, химия |
| 10–11 | + высшая математика |

Необязательное поле `offerExtra` (`title`, `text`, `badge`) добавляет четвёртую ступень в оффер-стек только этого сегмента — сейчас заполнено у 1–4.

**Сменить формулировку про места** — одна строка в `segments/*.json`, без правок кода:

```json
"topbar": { "seatsTemplate": "Осталось {n} {seats} в этом наборе" }
```

`{n}` — число, `{seats}` — «место / места / мест» со склонением по правилам русского языка. Фраза подставляется одинаково в верхнюю плашку, первый экран и форму.

### `offer.json` — параметры оффера

| Параметр | Сейчас | Смысл |
|---|---|---|
| `trialPrice` | `1500` | Перечёркнутая стоимость пробного урока |
| `trialFinal` | `0` | Итоговая цена пробного |
| `discount` | `1500` | Скидка на первое платное занятие |
| `lessonPrice` | `null` | Цена занятия. Пока `null`, цена «после скидки» не выводится — только размер скидки (зависимость D5) |
| `timerMinutes` | `15` | Срок жизни скидки от первого визита |
| `seatsMin` / `seatsMax` | `3` / `10` | Диапазон случайного числа мест |
| `promoCode` | `""` | Промокод 100%. **Пустой — `build:strict` падает** (зависимость D3) |
| `storageVersion` | `"v1"` | Версия ключа `tst_<версия>_<сегмент>`. Смена версии сбрасывает места и таймеры у всех посетителей |
| `ttlDays` | `30` | Срок жизни записи посетителя |

### Остальные файлы

- `tutors.json` — репетиторы: имя, имя в родительном падеже (для кнопки «Закрепить урок у …»), пол, фото, предметы, стаж, уроки, рейтинг. `placeholder: true` — карточка без выдуманного человека (сейчас так показан русский язык, зависимость D1).
- `site.json` — телефон, юридические ссылки, рейтинги площадок, `ymCounterId` (пока `null` — события идут только в `dataLayer`), а также: `grades` — все поддерживаемые классы (1–11; классы вне своего сегмента открываются в форме кнопкой «Другой класс»), `subjects` — подписи предметов, `sourceNotes` — строка на первом экране для посетителей с известной площадки (ключи `avito`, `wb`, `ozon`; без метки строка не показывается).
- `schedule.json` — шаблон недели для слотов: `leadHours` 3 (не раньше чем через 3 часа), `daysToShow` 3 дня со свободным временем, `holdMinutes` 10 (холд места), `lessonMinutes` 45. Реальное расписание репетиторов не используется.
- `stopwords.json` — запрещённые в текстах обещания результата. Сборка падает, если стоп-слово попало в контент сегмента.

## Как это работает

- **Места и таймер.** При первом визите сервер ставит cookie `tst_v1_<сегмент>` = `места.дедлайн.вариант` на 30 дней; браузер зеркалит её в `localStorage`. Если оба хранилища недоступны (встроенные браузеры, приватный режим), число мест и A/B-вариант считаются из идентификатора посетителя — перезагрузка их не меняет, дедлайн в этом режиме живёт в рамках вкладки.
- **Форма.** Три шага, холд места на 10 минут, валидация при уходе из поля, «билет» показывается только после подтверждения заявки из CRM. Повторная отправка той же брони не создаёт дубль (ключ идемпотентности, 10 минут в памяти процесса).
- **A/B.** Вариант `a`/`b` назначается вместе с записью посетителя; в вёрстке присутствуют оба текста, лишний скрывается до первой отрисовки. Переопределение для QA — `?v=a` / `?v=b` (сохранённый вариант не перезаписывается).
- **Аналитика.** 10 событий воронки (`lp_view`, `lp_scroll_50`, `lp_form_start`, `lp_step_1…3`, `lp_tutor_select`, `lp_submit`, `lp_success`, `lp_timer_expired`) уходят в `dataLayer`, а при заданном `ymCounterId` — целями в Яндекс Метрику. Персональные данные в события не попадают.
- **Безопасность.** Отдаются только `/assets/`, `/css/`, `/js/` с разрешёнными расширениями: исходники, контент-JSON, `server.mjs` и `package.json` по HTTP недоступны. Страницы отдаются с `Content-Security-Policy`, где разрешены ровно инлайн-скрипты этой сборки (хэши считает `build.mjs` и пишет в `dist/manifest.json`). Атрибуты `style=` запрещены — сборка падает. Персональные данные не пишутся в журналы.

## Инструменты в `tools/`

| Скрипт | Когда нужен |
|---|---|
| `size-check.mjs` | Часть `npm run build`: бюджеты CSS/JS gzip на страницу |
| `convert-fonts.py` | Однократно: Graphik TTF → WOFF2 (`pip install fonttools brotli`) |
| `convert-images.py` | Однократно: фото репетиторов → WebP/AVIF в 4 размерах (Pillow ≥ 11.2) |
| `overflow.mjs` | Отладка вёрстки: показывает элементы шире вьюпорта — `node tools/overflow.mjs 5-9 768` |
| `shoot.mjs` | Отладка вёрстки: скриншоты блока на заданных ширинах |
| `demo-build.mjs` | Сборка превью для статического хостинга: пути с префиксом, `noindex`, корневая страница со ссылками — `node tools/demo-build.mjs tutoronline-segment-landings demo` |

Превью вёрстки опубликовано на GitHub Pages: https://vsevolodyakushev.github.io/tutoronline-segment-landings/ — ветка `gh-pages`, собирается `demo-build.mjs`. Отправка заявки там не работает (нужен `server.mjs`), страницы закрыты от индексации.

`overflow.mjs` и `shoot.mjs` — вспомогательные скрипты разработки, в деплой не входят; обоим нужны установленный Playwright и запущенный сервер.

## Перед запуском

Зависимости от заказчика (`specs/001-segment-landings-quiz/research.md`, D1–D6):

- [ ] **D1.** Репетиторы по русскому языку: фото, имена, стаж и согласие на рекламу. Пока — карточка «Подберём репетитора по русскому» без имени в кнопке и «билете».
- [ ] **D2.** Согласие репетиторов-математиков на использование в рекламе (данные взяты из базового лендинга).
- [ ] **D3.** Реальный промокод 100% → `offer.json` → `promoCode`. Без него `npm run build:strict` падает, а на «билете» нет кода.
- [ ] **D4.** Идентификатор счётчика Яндекс Метрики → `site.json` → `ymCounterId`. Пока события идут только в `dataLayer`.
- [ ] **D5.** Подтверждение 1 500 ₽ как реальной цены занятия. После подтверждения можно задать `offer.json` → `lessonPrice`, и цена «после скидки» появится в оффере.
- [ ] **D6.** Проверка допустимости внешних ссылок в рекламных форматах Avito, Wildberries и Ozon (вне объёма разработки).

Перед публикацией:

- [ ] `npm run build:strict`, `npm test` и `npm run test:e2e` проходят без падений.
- [ ] По одной помеченной тестовой заявке на каждый сегмент в реальный CRM: имя `ТЕСТ лендинг 1-4` / `5-9` / `10-11`, разрешённый номер. Проверить 6 полей вебхука и читаемость `info` (номер брони, сегмент, класс, предмет, репетитор, слот МСК, промокод, скидка, вариант, источник, объявление).
- [ ] Ручные сценарии Q16, Q18 и Q20 пройдены, результаты записаны в раздел «Проверка».
- [ ] Размещение по `SERVER_SETUP.md`: `PUBLIC_ORIGIN` задан, HTTPS работает, cookie уходит с флагом `Secure`.
