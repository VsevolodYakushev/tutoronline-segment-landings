# Размещение на личном сервере

Три лендинга и обработчик заявок лежат в одной папке. React, бандлеры и внешние пакеты для работы не нужны: в рантайме используются только встроенные модули Node. Нужен **Node.js 22 или новее** с доступом по HTTPS к `profile.tutoronline.ru`.

Отличие от базового лендинга: страницы не лежат готовыми файлами, а собираются из `src/` в `dist/`. **Без сборки сервер отдаст 404.**

## Локальный запуск

```sh
npm install
npm run build
npm start
```

Откроется `http://127.0.0.1:8765/5-9/`. Также обслуживаются `/1-4/` и `/10-11/`, а `/` перенаправляет на `/5-9/` с сохранением параметров ссылки. Обычный файловый хостинг или Python HTTP server не выполняет `server.mjs` — форма с ним работать не будет.

## Публичный сервер

1. Скопируйте папку сайта на сервер (вместе с `src/`, `assets/`, `build.mjs`, `server.mjs`, `package.json`).
2. Выполните `npm ci --omit=dev` (или скопируйте папку без `node_modules` — для рантайма зависимости не нужны).
3. Соберите страницы в строгом режиме: `NODE_ENV=production node build.mjs` или `npm run build:strict`. В строгом режиме сборка падает, если не задан промокод или не заполнены блоки сегментов.
4. Запустите Node постоянной службой от отдельного непривилегированного пользователя.
5. Укажите `PUBLIC_ORIGIN` — адрес сайта с протоколом, без пути и завершающего слеша.
6. Настройте HTTPS и обратный прокси на `127.0.0.1:8765`.
7. Проверьте по одной помеченной тестовой заявке на каждый сегмент и найдите их в CRM.

Пример запуска (замените адрес на свой):

```sh
PUBLIC_ORIGIN=https://lp.example.com TRUST_PROXY=1 NODE_ENV=production node server.mjs
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PUBLIC_ORIGIN` | пусто | Публичный адрес сайта. Проверяет заголовок `Origin` у заявок и включает флаг `Secure` у cookie посетителя, если адрес на `https:` |
| `TRUST_PROXY` | выкл. | `1` — брать адрес клиента из `X-Real-IP`, но только когда запрос пришёл с localhost (от своего же прокси) |
| `LEAD_WEBHOOK_URL` | адрес CRM TutorOnline | Куда уходит заявка. Допускается только `https:` |
| `LEAD_WEBHOOK_FORMAT` | `form` | `form` — `application/x-www-form-urlencoded`, `json` — тело JSON. Других значений сервер не принимает и не стартует |
| `NODE_ENV` | пусто | `production` включает строгий режим сборки (`build.mjs`) |
| `PORT` / `HOST` | `8765` / `127.0.0.1` | Куда слушать. По умолчанию только localhost; для контейнера при необходимости `HOST=0.0.0.0`, но не публикуйте порт в обход HTTPS-прокси |

Пример блока Nginx внутри уже настроенного HTTPS-сервера:

```nginx
location / {
    proxy_pass http://127.0.0.1:8765;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 25s;
    client_max_body_size 16k;
}
```

Это фрагмент настройки прокси, не готовая настройка домена и сертификата. `TRUST_PROXY=1` принимает адрес клиента из `X-Real-IP` только от локального прокси; Nginx должен перезаписывать этот заголовок, как в примере.

## Что отдаёт сервер

| Адрес | Ответ |
|---|---|
| `/` | 302 на `/5-9/` с сохранением параметров |
| `/1-4/`, `/5-9/`, `/10-11/` | Страница сегмента, `Cache-Control: no-cache` |
| `/1-4`, `/5-9`, `/10-11` (без слеша) | 301 на адрес со слешем |
| `/assets/…`, `/css/…`, `/js/…` | Статика из `dist/`. Файлы с хэшем в имени — `immutable` на год, остальные на сутки |
| `POST /api/lead` | Приём заявки, передача в CRM |
| всё остальное | 404 |

Раздача идёт по белому списку: `src/`, `tools/`, `tests/`, контент-JSON, `server.mjs`, `build.mjs`, `package.json` и `dist/manifest.json` по HTTP недоступны.

## Cookie посетителя

При первой отдаче страницы сегмента сервер ставит cookie `tst_v1_<сегмент>` = `места.дедлайн.вариант`, `Max-Age` 30 дней, `Path=/`, `SameSite=Lax`. Флаг `Secure` добавляется автоматически, если `PUBLIC_ORIGIN` начинается с `https:` — поэтому на публичном сервере переменную нужно задать обязательно. Персональных данных в cookie нет: только число мест, срок скидки и буква A/B-варианта.

## Заголовки безопасности

Страницы отдаются с `Content-Security-Policy`: `default-src 'self'`, скрипты и стили — только свои, плюс хэш встроенного скрипта именно этой сборки (считается при сборке и хранится в `dist/manifest.json`). Если в `src/content/site.json` задан `ymCounterId`, к политике автоматически добавляются адреса Яндекс Метрики (`script-src`, `img-src`, `connect-src`, `frame-src`).

Политику сервер берёт из `dist/manifest.json` и перечитывает её, когда файл меняется, — после пересборки перезапуск не нужен, заголовок сам подхватит новые хэши.

Дополнительно на всех ответах: `X-Content-Type-Options: nosniff` и `Referrer-Policy: strict-origin-when-cross-origin`. Если HTTPS настроен, добавьте `Strict-Transport-Security` на уровне Nginx.

## Вебхук и поля

Адрес по умолчанию уже задан в коде: `https://profile.tutoronline.ru/DataService.svc/SaveRegistrationRequest`.

Сервер отправляет POST с шестью полями:

| Поле | Значение |
|---|---|
| `name` | Имя из формы |
| `phone` | Телефон из формы |
| `email` | Email из формы; может быть пустым |
| `subject` | `Математика` или `Русский язык` |
| `landing` | Адрес страницы сегмента с пятью стандартными UTM-параметрами, если они были |
| `info` | Строка брони: номер, сегмент, класс, предмет, репетитор, слот по МСК, промокод, запрошена ли скидка, A/B-вариант, источник, ID объявления, согласие на рекламу, отметка об обязательстве прийти |

Поля, которых нет в формате приёмника, передаются внутри `info` — произвольные параметры URL, фрагмент адреса и cookies не передаются. Обязательное согласие на обработку персональных данных проверяется и на клиенте, и на сервере. Согласие на рекламу передаётся только как пометка в `info` и не должно автоматически считаться полученным в CRM.

Если ваш приёмник ждёт JSON, задайте `LEAD_WEBHOOK_FORMAT=json`.

## Подтверждение результата

После успешного HTTP-ответа сервер дополнительно ждёт явный признак успеха: `ok`, `true`, JSON с `success: true` / `Success: true` либо такой результат внутри `SaveRegistrationRequestResult`. Произвольный HTML, пустой HTTP 200 и отрицательный результат подтверждением не считаются — «билет» посетителю не показывается, вместо него предлагается телефон для записи.

Повторная отправка той же брони не создаёт дубль: браузер держит ключ попытки, сервер в течение 10 минут возвращает уже полученный результат, не обращаясь к вебхуку повторно. Автоматических повторов нет.

Защита от повторов, лимит частоты (30 запросов в минуту с адреса) и кэш сжатия живут в памяти одного процесса и сбрасываются при перезапуске. Для нескольких экземпляров сервера нужен общий механизм хранения. Персональные данные заявок в журналы не записываются; постоянного хранения или очереди заявок здесь нет.

## Что проверено, а что осталось

6 ноября 2026 локально проверены: сборка трёх страниц, недоступность исходников и контента по HTTP (404 на `/server.mjs`, `/package.json`, `/src/content/offer.json`, `/build.mjs`, `/dist/manifest.json`), наличие CSP с хэшем встроенного скрипта страницы.

Не проверялись: полный прогон `npm test` и `npm run test:e2e` (нужна среда с Node 22+), Lighthouse, встроенные браузеры маркетплейсов и реальные заявки в CRM. Работоспособность интеграции с CRM окончательно подтверждается только реальной тестовой заявкой по каждому сегменту — см. чек-лист «Перед запуском» в `README.md`.
