# Контракт: интенты и карта ключевых слов

Один шаблон лендинга разворачивается в страницы под каждое направление продвижения. Первый сегмент пути выбирает **интент** — заголовок первого экрана и предустановленные класс с предметом. Посетитель может сменить и то и другое.

## Три уровня контента

| Уровень | Файлы | Что держит | Сколько |
|---|---|---|---|
| Сайт | `src/content/site.json` | телефон, счётчик, классы 1–11, словарь предметов, строки площадок | 1 |
| Кластер | `src/content/segments/*.json` | аудиторию, боли, шаги урока, FAQ, список предметов фильтра, репетиторов | 3 |
| Интент | `src/content/intents/*.json` | заголовок, подзаголовок, бейдж, умолчания фильтра, meta | 19 |

Кластер отвечает на вопрос «кому мы говорим», интент — «о чём именно». Поэтому боли и FAQ не дублируются 19 раз, а заголовок не приходится писать один на весь кластер.

## Интент

```json
{
  "key": "oge-geometriya",
  "cluster": "5-9",
  "label": "ОГЭ геометрия",
  "defaultGrade": 9,
  "defaultSubjects": ["geometry"],
  "hero": {
    "title": "Бесплатный пробный урок с репетитором по геометрии",
    "subtitle": "Репетитор проверит темы по геометрии, покажет, где теряются баллы, и составит план до экзамена. 45 минут, бесплатно по промокоду.",
    "offerBadge": "Первый онлайн-урок бесплатно"
  },
  "meta": { "title": "…", "description": "…" },
  "heroTutorIds": null
}
```

| Поле | Правило |
|---|---|
| `key` | слаг `[a-z0-9-]+`, совпадает с именем файла и с адресом страницы `/<key>/`; не может совпасть с id кластера |
| `cluster` | существующий id из `segments/` |
| `label` | название направления для CRM и отчётов, на странице не показывается |
| `defaultGrade` | целое из `site.grades` |
| `defaultSubjects` | непустой массив, подмножество `subjects` кластера, у каждого предмета есть хотя бы один репетитор в `tutorIds` кластера |
| `hero.title`, `hero.subtitle` | обязательны, проходят стоп-лист FR-007; в строгом режиме обязаны различаться между интентами |
| `heroTutorIds` | `null` — брать трио кластера, либо массив известных id |

## Карта ключевых слов

`src/content/keywords.json` связывает метку объявления с интентом:

```json
{
  "keywords": {
    "repetitor-po-geometrii": { "intent": "oge-geometriya", "phrase": "репетитор по геометрии", "capacity": 6983 },
    "repetitor-po-geometrii-8-klass": { "intent": "oge-geometriya", "grade": 8, "phrase": "…", "capacity": 900 }
  }
}
```

На страницу влияют только `intent` и необязательный `grade`. `phrase` и `capacity` — справочные: по фразе сервер дополнительно опознаёт метку, записанную кириллицей, а ёмкость нужна инструменту ссылок. **Ни одно значение из этого файла не печатается на странице.**

Файл читается сервером на лету с перечиткой по mtime, тем же приёмом, что `dist/manifest.json` в `policyFor()`. Связку ключ↔направление можно менять без пересборки и без разработчика, а новый текст через неё протащить нельзя — внутри только идентификаторы.

## Выбор интента

| Вход | Поведение |
|---|---|
| `/oge-geometriya/` | основной путь, страница отдаётся сразу |
| `/?i=oge-geometriya` | 302 на путь интента |
| `/?i=repetitor-po-geometrii` | то же: `i` принимает и ключ интента, и ключевое слово |
| `/?utm_term=repetitor-po-geometrii-8-klass` | 302 на `/oge-geometriya/`, в строку запроса добавляется `grade=8` |
| `utm_term` кириллицей, в верхнем регистре, с `+` или `_` | нормализуется и опознаётся по `phrase` |
| неизвестная метка | страница отдаётся как есть, в журнал пишется предупреждение один раз на метку |
| метка, совпадающая с текущей страницей | редиректа нет — петли не возникает |

Строка запроса при редиректе сохраняется целиком, поэтому метки первого входа не теряются. `?grade` и `?subject` перекрывают умолчания интента.

## Передача дальше

- **Аналитика.** Каждое событие несёт `intent` и `utm_term` рядом с `segment`, `variant`, `utm_source`, `utm_content`.
- **Заявка.** `POST /api/lead` принимает `intent` (ключ) и `keyword` (метка). Сервер проверяет, что интент существует и принадлежит кластеру заявки; иначе `invalid_form`.
- **CRM.** В `info` добавлены пары «Направление» (label интента) и «Запрос» (метка) сразу после «Сегмента». Состав полей вебхука не менялся — их по-прежнему шесть.

## Чек-лист модерации

Маркетплейсы перепроверяют страницу периодически и по жалобам, поэтому правила такие:

1. **Каждая страница проходит модерацию самостоятельно.** Критерий не «понравится ли вариант», а «пройдёт ли он, если модератор откроет именно его».
2. **Голый адрес кластера — полноценная допустимая страница.** `/5-9/` не может быть «приличной версией» для проверяющего, пока интенты обещают что-то другое.
3. **Вариант выбирается только по ключу из адреса.** Никогда по user-agent, IP, рефереру или признакам посетителя: это клоакинг и основание для блокировки, даже если оба текста безупречны.
4. **Текста в ссылке нет.** В адресе только идентификатор; заголовки живут в контенте и проходят ревью. Подстановка ключевого слова в текст страницы запрещена — это и кривая грамматика, и дыра, через которую на брендированную страницу попадает произвольный текст.
5. **Условия одинаковы везде.** Скидка, «бесплатно», длительность урока совпадают в креативе, в заголовке, в оффере и в CRM. Интент меняет формулировку, не условие.
6. **Реестр живых текстов.** При правке заголовка интента запись в реестре ниже обязательна: при жалобе это единственный способ подтвердить, что показывалось.
