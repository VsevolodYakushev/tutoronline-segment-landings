# Один лендинг с интентами под ключевые слова Авито

## Context

Маркетинг отобрал в таблице «Ключи» 38 ключевых слов (отметка «Запускаем в работу» = Да), сгруппированных в 17 сегментов Авито и 3 кластера. Прогноз по таблице — 1 155 обращений в месяц при общей ёмкости ~115 000 человек.

Сейчас в проекте три отдельных лендинга (`/1-4/`, `/5-9/`, `/10-11/`) с одним заголовком на сегмент. Под 38 ключей это даёт расхождение между обещанием в объявлении и первым экраном: человек ищет «репетитор по геометрии», а попадает на «Тройка в четверти?» с выбранной математикой.

Задача: один лендинг (один шаблон, один контент-модуль, одна дизайн-система), в котором первый параметр адреса выбирает **интент** — заголовок «Бесплатный пробный урок с репетитором по ‹направлению›» и предустановленные фильтры класса и предмета, с возможностью выбрать другие. Ключевое слово остаётся в `utm_term` для сведения экономики.

Решения, принятые пользователем:
- адрес — **путь на интент** (`/ege-matematika/`) плюс запасной вход через `?i=` и `utm_term`;
- для английского, биологии, информатики и литературы репетиторов нет → **карточка «Подберём репетитора по ‹предмету›»** (приём уже работает для русского);
- **геометрия и литература — отдельные чипы** в фильтре, чтобы заголовок и форма совпадали.

### Что значит «один лендинг»

Шаблон, блоки, стили и логика — одни. Сборка разворачивает их в 22 статические страницы (19 интентов + 3 кластерных без интента). Это не клонирование: правка в шаблоне или в общем тексте меняет все страницы сразу, вручную никто ничего не дублирует. Статические страницы выбраны потому, что переживают срезание query-строки площадкой, не мигают заголовком и показывают модератору ровно ту же страницу, что и человеку.

### Главное ограничение, которое остаётся после этой работы

Из 19 интентов у 7 за предметом нет ни одного живого репетитора (английский ×3, биология ×2, информатика ×2), ещё у 3 — только заглушка или один человек (русский, литература, химия). Шаг «выберите репетитора» для них вырождается в одну карточку подбора. Технически запуск возможен, но английский — самый ёмкий предмет набора (~15 200 человек), и там это ударит по конверсии сильнее всего. Карточки реальных преподавателей надо добирать параллельно с запуском.

## Модель данных

Три уровня вместо двух. Файлы в `landings/src/content/`.

**Сайт** (`site.json`) — общее: телефон, счётчик, классы 1–11, словарь предметов, строки площадок.
Предметы расширяются с 5 до 10: `math, geometry, russian, literature, physics, chemistry, biology, informatics, english, highermath`.

**Кластер** (`segments/1-4.json`, `5-9.json`, `10-11.json`) — остаётся как есть: `grades`, `audience`, `pains`, `trialSteps`, `faq`, `extraBlocks`, `final`, `topbar`, `offerExtra`, `tutorIds`, `heroTutorIds`. Меняется только `subjects` — теперь это полный список чипов, доступных в фильтре кластера.

**Интент** (новый `intents/*.json`, 19 файлов) — всё, что зависит от ключевого слова:

```json
{
  "key": "oge-geometriya",
  "cluster": "5-9",
  "label": "ОГЭ математика и геометрия — геометрия",
  "defaultGrade": 9,
  "defaultSubjects": ["geometry"],
  "hero": {
    "title": "Бесплатный пробный урок с репетитором по геометрии",
    "subtitle": "Репетитор разберёт темы, где теряются баллы, и составит план до экзамена. 45 минут, бесплатно по промокоду.",
    "offerBadge": "Первый онлайн-урок бесплатно"
  },
  "meta": { "title": "…", "description": "…" },
  "heroTutorIds": null
}
```

**Карта ключей** (новый `keywords.json`) — 38 записей, `utm_term` → интент и необязательное уточнение класса:

```json
{
  "repetitor-po-geometrii": { "intent": "oge-geometriya" },
  "repetitor-po-geometrii-8-klass": { "intent": "oge-geometriya", "grade": 8 },
  "repetitor-po-matematike-10-klass": { "intent": "ege-matematika", "grade": 10 }
}
```

Файл читается сервером в рантайме с перечиткой по mtime — тем же приёмом, что уже применён для `manifest.json` в `policyFor()` ([server.mjs](landings/server.mjs)). Маркетолог меняет связку ключ↔интент без пересборки и без разработчика. Новый текст через этот файл протащить нельзя: в нём только идентификаторы.

## Изменения по файлам

### Контент
- `src/content/site.json` — 10 предметов в `subjects`.
- `src/content/tutors.json` — добавить 4 карточки подбора по образцу `russian-match` (`placeholder: true`, `photo: null`, метрики `null`): `english-match`, `biology-match`, `informatics-match`, `literature-match`. Математикам добавить `geometry` в `subjects` и в `subjectsLabel`.
- `src/content/segments/*.json` — расширить `subjects` и `tutorIds` под новые предметы кластера.
- `src/content/intents/*.json` — 19 новых файлов.
- `src/content/keywords.json` — 38 записей.

### Сборка
- `build.mjs` — `loadContent` читает `intents/` и `keywords.json`; цикл рендера идёт по интентам и кластерам, складывая в `dist/<key>/index.html`; `manifest.pages` получает `cluster` и `intent` у каждой страницы.
- `build.mjs → validate()` — снять устаревшее правило «репетитор должен вести math или russian» (оно заблокирует английского и биолога) и заменить на «хотя бы один предмет из `site.subjects`». Добавить проверки интентов: уникальный ключ в формате слага, существующий кластер, `defaultGrade` из `site.grades`, непустой `defaultSubjects` ⊆ `cluster.subjects`, у каждого предмета есть хотя бы один репетитор или карточка подбора, непустые `hero.title`/`subtitle`/`meta`. Прогнать стоп-слова (FR-007) по текстам интентов — без этого обещание результата приедет в продакшен через новый заголовок. Проверить карту ключей: все интенты существуют, классы валидны, дублей нет. В строгом режиме — требовать уникальности заголовков между интентами.

### Шаблоны
- `src/templates/page.mjs` — `renderPage({ intent, cluster, … })`; `data-intent` на `<html>`; `pageConfig` отдаёт `intent: { key, label, defaultGrade, defaultSubjects }` и `cluster`; ключ cookie в инлайн-скрипте головы — **по кластеру, а не по странице**, иначе счётчик мест и таймер сбросятся при переходе между интентами одного кластера.
- `src/templates/blocks/hero.mjs` — заголовок, подзаголовок и бейдж из `intent.hero`. Когда у предмета интента только карточка подбора, подпись под фото меняется на «Пробные онлайн-уроки ведут преподаватели TutorOnline» без имён — показывать трёх математиков под заголовком про биологию нечестно.
- `src/templates/blocks/quiz.mjs` — чипы классов из `cluster.grades` с нажатым `intent.defaultGrade`; чипы предметов из `cluster.subjects` с нажатыми `intent.defaultSubjects`; «Другой класс» по-прежнему открывает остальные из 1–11.
- `src/templates/blocks/tutors.mjs` — сейчас секция жёстко берёт `tutorIds.math`; сделать её зависящей от основного предмета интента с откатом на математику.

### Логика
- `src/js/quiz-state.mjs` — `createInitialState` берёт умолчания из интента, параметры адреса (`?grade`, `?subject`) перекрывают их. Остальная машина состояний не меняется.
- `src/js/main.mjs` / `analytics.mjs` — в базу событий добавить `intent` и `utm_term`.
- `server.mjs`:
  - маршрут по `manifest.pages` вместо регулярки `^/(\d+-\d+)/$` — так интенты и кластеры обслуживаются одним кодом, а несуществующий путь честно даёт 404;
  - `policyFor(pageId)` — CSP по странице;
  - cookie по кластеру;
  - новое: на любой странице при `?i=` или `utm_term`, который разрешается в другой интент, — 302 на его путь с сохранением всей query-строки; неизвестный ключ не редиректит, а отдаёт страницу как есть и пишет событие, чтобы опечатку в ссылке заметили;
  - `leadFields` — принимать `intent` и `keyword`, проверять интент по контенту, предметы — по `cluster.subjects`; в `buildInfo` добавить пары «Направление» и «Запрос». Контракт вебхука CRM остаётся из 6 полей.

### Инструменты и документация
- `tools/ads-links.mjs` (новый) — собирает `ads-links.csv`: ключевое слово, ёмкость, интент, готовый адрес с UTM. Это то, что маркетинг вставляет в кабинет.
- `tools/demo-build.mjs` — индекс превью со списком всех интентов по кластерам.
- `specs/001-segment-landings-quiz/spec.md` — сессия уточнений и требования FR-039…FR-045 (интенты, карта ключей, совпадение фильтров с интентом, передача ключа в CRM и аналитику, запрет подстановки текста из адреса).
- `specs/001-segment-landings-quiz/contracts/intents.md` (новый) — модель, карта ключей, чек-лист модерации: каждый вариант проходит проверку сам по себе; голый адрес кластера — полноценная страница; выбор варианта только по ключу из адреса и никогда по признакам посетителя; датированный реестр живых текстов.
- `contracts/lead-api.md`, `contracts/crm-webhook.md` — поля `intent` и `keyword`.
- `landings/README.md` — как добавить интент и как собрать ссылку для объявления.

### Тесты
- `tests/unit/quiz-state.test.mjs` — умолчания из интента и перекрытие параметрами.
- `tests/server/` — маршрутизация путей интентов, редирект по `utm_term`, заявка с интентом и ключом, отказ при предмете вне кластера.
- `tests/build/` — падение валидации на неизвестном кластере, предмете без репетитора, стоп-слове в заголовке интента, дубле ключа.
- `tests/e2e/` — три представительных интента: правильный H1, предвыбранные чипы, смена предмета и класса, бронь до билета.

## Этапы

1. **Контент-модель и сборка** — предметы, карточки подбора, 19 интентов, карта ключей, новая валидация, рендер 22 страниц.
2. **Шаблоны и фильтры** — hero, квиз, секция репетиторов, умолчания в машине состояний.
3. **Сервер** — маршруты, CSP, cookie по кластеру, редирект по `utm_term`, заявка с интентом.
4. **Аналитика и CRM** — `utm_term` и интент в события и в `info` заявки. Без этого экономику по ключу не свести, а это главная цель запуска.
5. **Тексты** — 19 заголовков и подзаголовков, meta, проверка по стоп-листу.
6. **Документация, ссылки для кабинета, превью** — `ads-links.csv`, спека, README, обновление демо на GitHub Pages.

## Проверка

На этой машине Node 16, встроенный тест-раннер и часть синтаксиса проекта не работают (нужен Node ≥22), поэтому порядок такой:

1. `node build.mjs --strict` — должен собрать 22 страницы и упасть на подсунутых ошибках: интент с неизвестным кластером, предмет без репетитора, стоп-слово в заголовке, дубль ключа.
2. Разовые скрипты на чистых модулях (как делали раньше): умолчания `createInitialState` для 3–4 интентов, разрешение `utm_term` через карту ключей, `leadFields` с интентом и ключом.
3. Живой сервер `node --experimental-fetch server.mjs`: `/oge-geometriya/` отдаёт 200 с нужным H1; `/5-9/` по-прежнему 200; `/?utm_term=repetitor-po-geometrii-8-klass` даёт 302 на `/oge-geometriya/?grade=8&…`; несуществующий путь — 404; CSP присутствует на каждой странице.
4. POST `/api/lead` с интентом — в `info` появляются «Направление» и «Запрос», состав полей вебхука остаётся из шести.
5. Визуально: превью на GitHub Pages со всеми интентами, проверка первого экрана без прокрутки на 360×560 и чипов предметов при 10 вариантах.
6. Полный прогон `npm test` и e2e — на машине с Node 22 (остаётся открытой задача T070).

## Что остаётся за рамками и требует решения отдельно

- **Репетиторы по английскому, биологии, информатике, литературе** — запуск идёт с карточками подбора, реальные карточки добираются отдельно. По английскому это критично: ~15 200 человек ёмкости.
- **Геометрию и литературу ведут те же преподаватели, что математику и русский** — заложено как допущение, требует подтверждения методиста до публикации.
- **Доходимость параметров с площадок** — выбранная схема с путём не зависит от неё, но запасной вход через `utm_term` имеет смысл проверить по одной тестовой ссылке на Авито, WB и Ozon.
- **A/B заголовков** — каждый интент выпускается с одним текстом (`?v=a|b` остаётся в коде, но hero его не использует). Иначе 19 интентов × 2 варианта дадут ячейки, в которых нечего считать: по прогнозу на мелкие сегменты приходится 15–30 обращений в месяц.
- **Семь отложенных сегментов** таблицы («Подготовка к школе» с ёмкостью 13 164, математика 2–4, чтение, ментальная арифметика) — вне набора, модель данных к ним готова.
