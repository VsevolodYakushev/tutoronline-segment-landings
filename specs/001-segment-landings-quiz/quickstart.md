# Quickstart: проверка трёх лендингов с квиз-формой

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

Это руководство по запуску и проверке, а не по реализации. Подробности полей — в [data-model.md](data-model.md) и [contracts/](contracts/).

## Предварительные условия

- Node.js 22+ (проверено на 24.15).
- Для E2E — браузеры Playwright (`npx playwright install chromium webkit`).
- Для проверки CRM — разрешённый тестовый номер телефона.

## Сборка и локальный запуск

```sh
cd landings
npm install                 # только dev-зависимость @playwright/test
npm run build               # build.mjs → dist/1-4, dist/5-9, dist/10-11
npm start                   # node server.mjs → http://127.0.0.1:8765/
```

Тестовый вебхук вместо CRM (ничего не уходит в TutorOnline):

```sh
LEAD_WEBHOOK_URL=https://<тестовый-приёмник> npm start
```

## Автоматические проверки

```sh
npm test                    # node --test: склонение, состояние, таймер, слоты, маска, квиз, info, bookingId, isConfirmed
npm run test:e2e            # Playwright: Chromium + WebKit × 360/390/768/1024/1440
```

Ожидаемый результат: все тесты зелёные, в отчёте E2E — 0 падений.

## Перед публичным запуском

1. Получить зависимости D1–D5 из [research.md](research.md#открытые-зависимости-от-заказчика-не-блокируют-план).
2. Отправить по одной помеченной тестовой заявке на сегмент в реальный CRM (Q13 на production-вебхуке).
3. Пройти Q20 на реальных устройствах.
